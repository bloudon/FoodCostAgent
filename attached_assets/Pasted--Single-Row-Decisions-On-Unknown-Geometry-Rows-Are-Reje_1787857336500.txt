# Single-Row Decisions On Unknown-Geometry Rows Are Rejected With 409

**Priority:** Blocker — June cannot be approved
**Environment:** FnB Dev, Bay Hill CC `61971215-e3ed-49f3-8afc-6dbe1eef1fcc`
**Batch:** `8f0e7827-1252-4914-b5fa-60e5a3db2f5c` (June_2026, 5,409 rows, pending review)
**Blocking row:** #3442 — Mushrooms - Blends/Mix, code `26045`, Mr. Green's Produce, Produce Walk-in

> **Numbering note:** two shipped tickets are both recorded as #1256 (descriptive-code identity, and the revived #1255 parser scope). Please assign this a fresh number and resolve that collision.

## Summary

A row with unresolvable pack geometry cannot receive a review decision. `PUT .../review-decisions` returns **409 every time**, no decision is written, and the batch can never reach zero outstanding decisions — so **Approve stays permanently disabled**.

June is otherwise complete: 165 of 166 decisions saved. This one row blocks the batch.

## Reproduction (100%)

1. Open June batch → Preview → filter STATUS = **Pack check**
2. Expand row **3442**, Mushrooms - Blends/Mix (`26045`)
3. Panel shows *Pack Evidence Incomplete*; the only offered action is **Create as separate variant**
4. Click it
5. `PUT /api/inventory-import/orderly/batches/{batchId}/review-decisions` → **409**
6. Row displays *"Save failed — choose a decision again to retry."* Retrying always fails.

## Evidence that this is not a stale-revision conflict

* Persists after a **full page reload** (fresh revisions loaded)
* `GET review-decisions` confirms **no saved decision exists for row 3442** — this is a *first* write, so there is no prior revision to conflict with
* Saved decision count stays at 165; nothing is written
* The same session successfully wrote 165 other decisions through the same endpoint

## Isolation — the shared contract is fine

Both bulk paths write cleanly through the same endpoint in the same session:

| Path | Rows | Result |
|---|---|---|
| Category 1 bulk link ("Link 32 compatible codes") | 88 rows / 32 groups | `PUT` **200** |
| Category 2 bulk variants ("Create 30 new variants in bulk") | 78 rows / 30 groups | `PUT` **200** |
| **Row 3442 single-row, unknown geometry** | 1 row | **409, always** |

All 165 saved decisions are at `revision: 1`. So the failure is specific to **a single-row decision on a row whose pack geometry is unresolvable**.

## Likely cause

The identity-boundary guard added during the Category 1 bulk-link work rejects a shared code-group decision when the authoritative preview says rows cross description/pack identity boundaries.

Row 3442 has *unknown* geometry, not *incompatible* geometry. It has no boundary to compare against, and the guard appears to be treating "unknown" the same as "crosses a boundary." Since single-row decisions now apply group-wide, the guard fires and rejects the write.

If that is correct, **every unknown-geometry row that lands in a decision bucket is undecidable**, not just this one. June carries 249 unknown-geometry rows; only this one currently requires a decision, which is why it surfaced.

## Done looks like

* A single-row decision on a row with unresolvable pack geometry saves successfully.
* The identity-boundary guard continues to reject genuinely incompatible cross-boundary decisions — unknown geometry must not be conflated with incompatible geometry.
* A rejected decision returns an error the operator can act on, distinguishing "stale revision, retry" from "not permitted, here is why". The current *"choose a decision again to retry"* invites an infinite retry loop on an action that can never succeed.
* Regression: an unknown-geometry row can be decided; an incompatible cross-boundary group decision is still refused.

## Out of scope

* Changing pack parsing, normalization, or the identity key.
* Making unknown geometry compare as compatible with anything.
* Approving June.
