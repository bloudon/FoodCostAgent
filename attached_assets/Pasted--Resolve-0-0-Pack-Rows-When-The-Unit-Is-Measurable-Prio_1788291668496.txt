# Resolve `0/0` Pack Rows When The Unit Is Measurable

**Priority:** Blocker — 25 July rows cannot be resolved; July approval is gated on this
**Environment:** Production, Bay Hill CC · batch `49d087c5-8e33-4bdc-ae06-821f71d2d231`
**Current build verified:** API `252335b4`, bundle `index-DBK-Ui4q.js`
**Current state:** 344 valid decisions, 27 stale, Approve disabled

---

## Summary

Orderly emits `0/0 <UNIT>` for items counted directly in a base unit rather than by case — typically open bottles on the bar. The parser reads `0/0` as "no pack information", so normalized total is unconfirmable, and every decision on those rows is rejected with:

> `The saved item for blank-code row 624 lacks compatible pack provenance`

The rows cannot be linked, and the only alternative creates a duplicate of a product that already exists in the catalog from May and June.

**The pack is not unknown.** `0/0` means no *case multiplier*. The unit is stated, and for these rows it is measurable.

---

## The evidence

July row 747, Maker's Mark, `0/0 LT`:

| Field | Value |
|---|---|
| Pack Size | `0/0 LT` |
| Package Price | **$37.00** |
| Total Units | 4.6 |
| Total Cost | **$170.20** |

$170.20 ÷ 4.6 = **exactly $37.00 per litre.**

The item is counted in litres, priced per litre, and internally consistent. Across all four Maker's Mark rows in July: 5.6 units, $207.20, $37.00/L throughout.

Titos `0/0 LT` carries Package Price $25.50 with zero on hand this month — same structure, no quantity.

---

## The distinction

This is the same measurable-versus-opaque split already established by **#1264** (preserve measurable Orderly units: GR, PT, Cup, KG, DZ, GAL, QT) and **#1277** (`1/1 Case` is genuinely opaque *because `Case` is not a measurable unit*).

| Pack | Unit measurable? | Correct treatment |
|---|---|---|
| `0/0 LT` | yes — litre | 1 × 1 × 1 LT |
| `0/0 750ML` | yes — millilitre | 1 × 1 × 750 ML |
| `0/0 EA` | yes — each | 1 × 1 × 1 EA |
| `0/0 Case` | **no** | remains unknown, unchanged |

**Every `0/0` row in the Bay Hill data uses a measurable unit.** Across May, June and July: 45 rows, units are only `LT`, `750ML`, and `EA`. There are no `0/0 Case` rows.

---

## Requested change

**When case and inner counts are zero or absent but the unit is measurable, normalize the row as `1 × 1 × <unit>` — counted directly in that base unit.**

Consequences:

* Normalized total becomes confirmable (1 LT, 750 ML, 1 EA) instead of zero
* Pack provenance can be satisfied, so blank-code rows link to their existing catalog item
* Cost per base unit is derived from Package Price, which the data already supports
* Value, quantity, and source evidence are unchanged

**Explicitly unchanged:** `0/0 Case` or any non-measurable unit stays unknown and continues to fail closed. This does not relax #1277, #1293, or the property-provenance rule — it corrects an input the parser is misreading, so those rules receive confirmable evidence rather than a false zero.
