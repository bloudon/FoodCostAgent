# Recipe Costing Validation — Bay Hill Sample

## Objective

Use the corrected Bay Hill recipe-harvest workbook as a controlled validation fixture against FnB's existing recipe, yield, UOM, pricing, and recursive costing architecture.

This is a validation/mapping task first.

Do not bulk-import the Orderly recipe catalog.
Do not normalize or "repair" the source workbook.
Do not change costing behavior merely to make Orderly totals match.

## Source fixture

Use:

- Recipes sheet
- Recipe Ingredients sheet
- Orderly Conversions appendix

Preserve all raw Orderly values exactly as harvested.

## Required mapping output

For every recipe/component row, report:

- source recipe/menu-item identity
- FnB target identity if matched
- source ingredient/component name
- FnB inventory item or sub-recipe match
- source quantity
- source UOM
- source line yield %
- FnB effective yield
- FnB conversion path actually used
- FnB costing unit
- FnB unit cost source
- FnB calculated line cost
- Orderly displayed line cost
- difference
- resolution status
- explicit failure reason where unresolved

Do not treat name-only matching as authoritative where ambiguity exists.

## Required failure taxonomy

Do not collapse unresolved cost into generic `$0`.

Classify at minimum:

- resolved
- missing inventory match
- missing price
- stale/unusable price
- missing conversion
- dimensionally incompatible conversion
- unresolved sub-recipe
- source zero-cost line
- incomplete/empty source recipe
- source-data ambiguity
- other explicit reason
