Do not rely solely on the raw JSON file byte SHA-256 for APPLY authorization.

We have already observed different raw-file hashes reported across handling of the source artifact.

Maintain both:

1. raw source-file SHA-256 for chain-of-custody evidence
2. canonical logical fingerprint generated from a deterministic serialization of the reviewed source relationships

The canonical fingerprint should be insensitive to harmless JSON formatting or object-key ordering, but sensitive to any substantive source relationship change.

Document the canonicalization rule.

Future APPLY must verify:

- expected property
- expected manifest identity
- canonical logical fingerprint
- current DB-state revalidation

If substantive source evidence changed, refuse APPLY and require a fresh preview.
