## 2. `999900 / No Account`

Appears in all three months of inventory data but **is not in the chart of accounts** — it is Orderly's unassigned placeholder.

Per the #1275 draft, it must:

* Remain visible as source evidence, unchanged
* Display as **"Unassigned / review required"**
* Be included in grand totals where appropriate
* Be **excluded** from classified COGS / Revenue / Other Expense subtotals
* **Never** silently inherit an account

If the CoA is loaded as-is, this code has no destination. It needs an explicit one before category mapping runs.

## 3. Category → account mapping

The mapping is **1:1 with Category** and authoritative. Orderly's own export note states it:

> GL Account is assigned per ingredient via a single category dropdown on the ingredient record; the ingredient itself has no separate numeric GL field. This table is the authoritative Category → numeric GL Account mapping and applies uniformly across all ingredients assigned to each category.

Verified against the source: **25 of 26 GL codes used by inventory match the chart exactly** — same number, same name, across all three months. Zero name discrepancies. The single exception is `999900`.

So category names map directly to account names. After the re-run, every created category should carry its account with no manual mapping step.

**Verification after May's approval:** every category has a non-null `accountingAccountId`, and `510800` resolves to Wine, `511200` to Liquor, `501000` to Dry Goods.

## 6. Operator procedure

Follow the Production Seed Runbook v1.0 §3. The steps most easily got wrong, each of which caused a real defect in earlier runs:

1. **Pre-bulk gate.** Open the Category 2 bulk, record every listed item, close **without confirming**. Check all of them — not only those flagged. The duplicate warning fires only on cross-vendor candidates, so unchanged rows and unflagged switches are invisible to it. This caught 7 items in July that were never flagged.
2. **Compare against the immediately prior approved month**, not the union of all prior months, and by **product name and Item Code together**. A cross-vendor switch brings a new code, so code-only comparison hides it.
3. **Cross-vendor links before the bulk.** Confirming the bulk first overwrites saved `link_vendor_pack` decisions.
4. **Check every page.** The list caps at 100 with no search. July's bucket held 160 rows across two pages.
5. **Verify server-side after each step** — `GET /api/inventory-import/orderly/batches/{id}/review-decisions`. The UI counter lags and rows keep their old status until re-render.
6. **Never retry a slow approval.** 60–130 seconds is normal. Idempotency is unverified and approved batches cannot be discarded.
