I only want three small tightenings before Replit starts.

First, for **Class A**, I would make “equivalent pack geometry” explicit rather than subjective. The classifier should state exactly which normalized fields must agree and which source-string differences are ignorable. For example, raw pack text may differ cosmetically while normalized purchase unit and quantity-per-purchase-unit are equivalent. We need the report to show the normalization rule used, otherwise “equivalent” can drift into opinion.

Second, the “price fields” comparison in Gate 1 should be diagnostic only. Different current/last prices should **not automatically move a group out of Class A** if the purchasing identity and pack are otherwise proven identical. Duplicate vendor rows can naturally have different stale/latest price snapshots. What matters is preserving all dated price history and selecting the survivor without losing chronology.

Third, the dynamic reference enumeration should distinguish between:

* actual DB/schema references,
* repo-level soft references/IDs,
* audit/provenance fields that store IDs without FK semantics.

That way the apply gate can prove nothing was missed without treating every incidental textual reference as something to repoint.
