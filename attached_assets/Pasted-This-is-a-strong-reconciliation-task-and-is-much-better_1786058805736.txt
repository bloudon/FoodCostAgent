This is a strong reconciliation task and is much better scoped than #981. The repository structure and `MOBILE_ARCHITECTURE.md` are publicly visible, so the historical source is available for the agent to inspect. ([GitHub][1])

I would make **four changes before running it**.

## 1. Do not let the task both recommend and execute consolidation

The current task says:

> Recommend one future app and one of the three Floor Mode options, with rationale, for user approval.

But a later step says:

> Align the #981 artifact to the established auth flow... remove or quarantine any second implementations only after approval.

That mixes a discovery task with a potentially destructive implementation task. Replit may interpret “after approval” as approval occurring inside the agent flow and begin modifying code.

For #983, I would stop at:

* inventory
* comparison
* decision recommendation
* disposition plan
* documentation

Do **not** align, migrate, delete, or quarantine code inside this task.

Create a separate implementation task after you approve the report.

Replace the consolidation step with:

> Produce an implementation-ready consolidation plan, but do not modify, delete, quarantine, or migrate either implementation in this task.

## 2. Do not pre-decide that the historical contracts must be adopted unchanged

This line is slightly too rigid:

> The waste voice bridge (version 1) and embedded-route whitelist contracts from the historical repo are adopted unchanged.

They should be treated as the **presumptive baseline**, but the reconciliation may reveal that #981 uses a newer or more appropriate approach.

Better wording:

> Treat the historical waste voice bridge v1 and embedded-route whitelist as the current authoritative baseline. Identify any conflict or required change, but do not alter either contract without a separately approved architecture decision.

That preserves the existing work without making the review outcome artificial.

## 3. Floor Mode cannot be fully decided from the two repositories alone

The old app already confirmed there are no Floor Mode references. The current project may also lack enough information to make a product decision.

The task can recommend one of the three outcomes, but the actual decision should remain yours.

Change:

> The future of the separate Floor Mode product is explicitly decided.

to:

> The report recommends a Floor Mode outcome and identifies the product and technical evidence supporting it. The final decision is recorded only after user approval.

Otherwise the agent may invent a rationale from incomplete evidence.

## 4. Make the output files explicit

The task says “written reconciliation report,” but does not name it.

Require:

```text
docs/mobile-architecture-reconciliation.md
```

Also require a machine-readable disposition table—or at least a strict markdown table—so the next implementation task can act on it.

Suggested columns:

| Component | Historical file | #981 file | Capability | Keep source | Action | Reason | Risk |
| --------- | --------------- | --------- | ---------- | ----------- | ------ | ------ | ---- |

## PM recommendation

The likely outcome is still that the **historical app should be the functional baseline**, because it already contains the mature hybrid shell, authentication bridge, scan flows, catch-weight support, and voice-waste contract. The #981 artifact may contribute cleaner navigation or selected native UI pieces, but “newer” should not automatically mean “authoritative.”

The important thing now is to force #983 to deliver the comparison **without letting it quietly begin the merger**. Once you review the report, the next task can be a tightly controlled consolidation implementation.
