### 2. Report mode remains provably read-only

Report mode may:

- query source/import provenance
- inspect mappings
- inspect downstream references
- classify candidates
- calculate proposed canonical identities
- calculate reconciliation evidence

It must not:

- insert audit rows
- set supersession fields
- update mappings
- update inventory items
- create manifests
- normalize data
- repair anything

Readiness tests should explicitly prove zero writes from report mode.

### 3. Preflight must not become mutation

The operational preflight may verify:

- required tables
- required columns
- required indexes/constraints
- company/store/source-property binding
- expected migration/schema version where available

If something is missing:

`PRECONDITION_FAILED`

with a clear operator message.

Do not have the remediation CLI create or alter production schema automatically.

Production schema should arrive through the application's normal deployment/migration process.

### 4. Separate readiness from execution

#1126 Done means:

- merged code is deployable
- production-scope guard is correct
- schema preflight exists
- commands are documented
- tests/typecheck pass

It does NOT mean:

- production report was run
- report.json exists
- candidate groups were reviewed
- manifest was generated
- production apply was authorized

Those remain #1122 execution gates.

### 5. Operator commands must make the gates obvious

Document four distinct stages:

#### Report
Read-only.

#### Manifest
Requires:
- exact reviewed report
- exact approved source Item Codes
- explicit manifest ID

#### Apply
Requires:
- reviewed manifest
- operator identity
- production confirmation flag
- current schema/preflight PASS
- report/manifest freshness PASS

#### Reconcile
Read-only verification after apply.

There must be no shortcut command equivalent to:

`report-and-apply`
or
`apply-all-safe`
