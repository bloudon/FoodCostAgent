# PM Architecture Check — Recipe / UOM / Yield Migration Readiness

## Objective

Before we define the Orderly recipe-harvest spreadsheet, document the existing FnB recipe, yield, conversion, and sub-recipe architecture so the migration artifact maps into current FnB terminology rather than inventing a second model.

This is an evidence/report task only.

Do not change schema or behavior yet.

---

## Context

We are preparing to manually harvest a representative set of Orderly recipes into a spreadsheet for migration testing.

The goal is:

Orderly source recipe data
→ spreadsheet source artifact
→ existing FnB recipe/UOM architecture
→ recomputed FnB recipe cost
→ comparison against Orderly source cost

We specifically want to battle-test FnB’s current UOM and yield logic.

Claude has confirmed that Orderly exposes at least two distinct yield concepts:

1. Recipe-level yield
   Example:
   `Yield: 1 Units produced`

2. Ingredient-line Yield %
   Example:
   `100.00%`

The second appears to represent ingredient trim/loss or usable-yield behavior and must not be conflated with recipe-level output yield.

Claude also observed:

- Recipes / prep or batch recipes
- separate Menu Items
- sub-recipes used as ingredients
- Menu Item → Recipe → Sub-recipe → base ingredient chains
- an Orderly Conversions page with ingredient-specific unit conversions
- some incomplete/broken recipe/menu-item records with $0 cost

Before Claude extracts anything, we need the FnB-side contract.
