## Product decisions

**Mobile:** preserve the current hamburger-triggered sheet drawer. Do not add a bottom tab bar in this task. That would be a separate mobile-navigation redesign.

**More:** remains a normal rail destination linking to `/more`. No flyout, submenu, or nested disclosure.

**Desktop expansion:** use separate pinned and temporary-hover states. That is the correct model for avoiding content movement during casual hover while still allowing users to keep labels visible.

## Implementation caveats

The proposed structure is sound, but I would add these requirements:

* The temporary expanded panel must remain open while the pointer is anywhere inside its expanded width—not only over the original 72px rail.
* Give the overlay a clear `z-index`, background, border/shadow, and pointer events so content beneath it cannot be accidentally clicked.
* Do not activate hover expansion on touch-only devices. Use the existing mobile/tablet drawer at the applicable breakpoint.
* Hydrate `isPinned` after mount to avoid a flash or React hydration mismatch from reading `localStorage`.
* Disable compact-mode tooltips while the rail is temporarily expanded or pinned.
* Keyboard focus entering the rail should expand it; focus leaving the entire rail should allow it to close.
* Escape closes only temporary expansion. It should not unpin a user-pinned rail.
* Clicking a navigation item should not collapse a pinned rail.
* Use `prefers-reduced-motion` to reduce or disable the width animation.
* Temporary overlay expansion should not change the document width or introduce horizontal scrolling.
* The store selector and profile controls must remain usable in both compact and expanded states.

One technical simplification: use `SidebarProvider`’s open state for the **pinned layout state**, while managing temporary hover/focus expansion separately. Avoid repeatedly changing the provider’s persistent open state on mouse enter and leave.
