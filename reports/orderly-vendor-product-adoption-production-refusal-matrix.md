# Orderly vendor-product adoption production preflight — refusal matrix

| Refusal condition | Why it is unsafe | Operator action | Do not do |
| --- | --- | --- | --- |
| Missing company, store, source property, DB, build, source, manifest, or output argument | A preflight without an explicit reviewed identity is not bound to a safe target. | Record the reviewed value in the rollout approval and rerun. | Guess a value or use a default scope. |
| `NODE_ENV` is not `production` | Production readiness output must be generated by the planned production deployment. | Stop; use the approved production operator environment. | Treat a DEV result as production readiness. |
| Git SHA, API version, build ID, or clean tree differs | The reviewed code is not the code being checked. | Deploy the reviewed build or restart review for a changed build. | Continue after changing code in place. |
| Local active API `/api/build-info` is unavailable, has no `APP_BUILD_ID`, reports another service identity, or exposes a different build ID | A newer checkout can otherwise inspect production while the serving API is still an older artifact. | Restart the reviewed API with the approved `APP_BUILD_ID`, verify the endpoint on the reviewed loopback listener port, then rerun from the beginning. | Trust the standalone preflight checkout or provide another URL. |
| Raw source SHA or canonical source fingerprint differs from the manifest | The immutable evidence changed, even if filenames look similar. | Stop; create a new preview/evidence review process. | Reuse the old manifest or alter a hash. |
| Manifest checksum/ID is invalid | The manifest could have been edited or is not the accepted frozen artifact. | Retrieve the original reviewed artifact and re-verify it. | Hand-edit, regenerate, or “fix” the manifest under this rollout. |
| DB host, port, or database differs | The process may be connected to a different environment or tenant. | Stop and resolve deployment/database configuration with operations. | Override the expected DB value to make it pass. |
| Required schema table, column, index, uniqueness, predicate, or indexed key order is missing/mismatched | The normal application schema is incomplete; later APPLY may not preserve identity/integrity. | Deploy and verify the normal migration, then rerun preflight. | Run schema migrations from the preflight or add ad hoc indexes. |
| Missing, duplicate, inactive, cross-company, or wrong-store binding | The source property is not safely authorized to the reviewed destination. | Resolve through the normal binding/authorization process and obtain renewed PM approval. | Redirect the binding manually or substitute another store. |
| Duplicate vendor/SKU identity, duplicate Orderly mapping, or orphan/cross-company mapping | The later operation cannot prove one stable vendor-product target per frozen identity. | Stop and route for separate data-integrity remediation and review. | Pick a “best” row, merge data, or alter mappings under this rollout. |
| Catalog fingerprint changes between beginning and end of preflight | Active writers make readiness evidence stale before it is recorded. | End the attempt, schedule the narrow writer-quiescence window, and rerun from the beginning. | Continue, compare only one count, or reuse the earlier report. |
| Preflight report says anything other than zero DB writes | The read-only safety boundary has been violated or cannot be proven. | Stop, preserve sanitized evidence, investigate before a new attempt. | Run preview or APPLY to see whether it “worked anyway.” |
| Preflight passes but PM has not authorized production preview | Readiness is not mutation or classification authorization. | Obtain PM approval for the exact report/build/window. | Run production preview or APPLY. |
| 112 held conflicts appear | Held evidence is excluded from the reviewed safe population. | Record them as non-blocking held rows and keep them untouched. | Resolve, remap, or create vendor products for held rows. |
